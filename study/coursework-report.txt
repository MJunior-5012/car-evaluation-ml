Decision Tree Classification on the Car Evaluation Dataset
Decision trees are supervised learning algorithms that are used for classification and regression tasks. They work by splitting data into subsets based on different feature values which aims to then increase class purity at each step. Their structure resembles a flow chart, where the internal nodes represent class feature tests and leaves represent the class predictions. Decision trees are widely used in machine learning systems for things such as medical diagnosis support tools as well as fraud detection systems and risk assessment models which is mainly because of their interpretability.
In the classification trees, the Gini index is the measure of impurity used to determine the best feature split possible. It shows the probability of wrongly classifying a random chose sample if it were labelled according to the distribution of classes in a node. A gini value of 0 shows perfect purity which means all samples belong to one class. The end goal of a decision tree algorithm is to minimize Gini impurity at each split.
The data set that was used in this project is the car evaluation dataset from the UCI Machine learning repo. The dataset used contains 1,728 instances and 6 categorical features as well which are buying, maint, doors, persons, lug_boot, and safety. The target variable “class” categorises cars into four classes which are, unacceptable, good, and very good.
When looking into the data set more, the feature summary confirmed that all variables are categorical and that there are also no missing values in the features or the target variable either. The dataset shape is 1728, 6 for X and 1728, 1 for y, which confirms complete data integrity. Since decision trees need numerical inputs, label encoding eas used to covert categorical values into integers. Each feature column was encoded separately, and the labels were also encoded into numeric from. This encoding does not distort tree performance significantly because the decision trees split on thresholds rather than assuming linear connections between encoded values.
The data set was split into training and testing sets using a 80/20 split with stratification. What stratified splitting does is ensure that the class distribution remains consistent in both sets. This is important because uneven class representation could make unfair evaluation metrics. A 80/20 split was chosen to allow sufficient training data while keeping a reliable test set for evaluating generalisation performance. 
With the whole structure of the dataset, the “unacceptable” class is likely the easiest to recognize because it dominates the dataset and is strongly linked with low safety or high maintenance or buying costs. The lesser classes, particularly “very good”, are likely harder to classify because they occur less frequently and need more specific combinations of feature values. 
Two decision trees were trained using Scikit learn, one shallow tree with max_depth and one unrestricted tree with no depth limit. 
The depth 2 model achieved training accuracy of 0.7670. The fact that test accuracy is slightly higher than training accuracy suggests that the model generalises reasonability well but lacks sufficient complexity to capture all the patterns in the data. With only two levels of splits, the model is limited to how precisely it can separate the four classes. This shows the concept of underfitting, the tree it too simple to model the data set fully.
On the other hand, the unrestricted tree achieved a prefect training accuracy of 1.0 and a test accuracy of 0.9855. The perfect training accuracy indicates that the tree memorised the training data fully, producing pure leaves. The high test accuracy shows that the dataset contains highly separable patterns, allowing deep trees to generalise well despite the high complexity. However, the difference between 1.0 and 0.9855 still shows slight overfitting, as the model performs even worse on unseen data.
The training vs test accuracy shows that training accuracy increases slowly as depth increases, eventually reaching 1.0. Test accuracy starts to increase as the model gains more power, then stabilises at high levels. The gap between training and test accuracy widens ad greater depths, showing the bias variance trade off. Shallow trees have high bias but low variance , while deeper trees reduce bias but increase variance
  These results show the nature of the decision trees. At each split, the algorithm chooses the feature and threshold that locally minimise impurity. As depth increases, the tree continues partitioning until the leaves become increasingly pure, which could then lead to it being able to memorize specific training patterns.
The second phase involved implementing a decision tree classifier from scratch using only NumPy and basic some python functions, it had to be from scratch therefore no built in tree classifiers were used. 
The first thing I had to do was implementing the Gini index function. The function calculates the weighted impurity of two smaller groups after a potential split. For each group, the class proportions are computed then squared, and then summed. The impurity is then calculated as 1 minus the sum of squared proportions. The overall Gini score is the weighted average of impurities across both groups. This secures full control over hoe impurity id computed and shows understanding of the mathematical foundation behind decision tree splitting.
After that process, the get_split function iterates over every feature and every possible value in the dataset to determine the split that produces the lowest Gini score. This brute force way mirrors the logic used internally by decision tree algorithms  but without optimisations such as sorted thresholds. The functions stores the best feature index, thresholds value, value, gini score and resulting groups.
The tree building process uses recursion, therefore the split function creates child nodes until a maximum depth of 2 is reached or until end conditions are triggered. A minimum size parameter was included which allows for basic pre pruning control. When stopping conditions are met, the node then becomes terminal and it predicts the majority class within that group.
After training it from scratch with max_depth = 2, the test accuracy was recorded as 0.6994. This is significantly lower than the 0.7775 achieved by scikit learns depth 2 model. The confusion matrix shows that the scratch tree predicted almost all of the instances as belonging to a single class which is class index 2. This indicates that the first split did not effectively separate classes, and the shallow depth limited further correction.
This behaviour shows the sensitivity if decision trees to split the selection. Since the scratch implementation tests splits using the condition[index], < value, and the data is label encoded rather then ordinally meaningful, some thresholds may not reflect meaningful categorical boundaries. Also, with depth restricted to  2, the tree cannot create enough partitions to distinguish minority classes effectively.
This confusion matric shows that class imbalance have strong effects. All samples were predicted as one dominant class, leading to poor recognition of other categories. This confirms that shallow trees can struggle when feature interactions are complex. 
There was also an additional extension implemented into this by including a min_size parameter in the split function. This acts as a simple pre pruning rule. If a node contains fewer samples then the minimum size, splitting stops and a terminal node is made.
Pre pruning helps reduce overfitting by preventing the model from creating very small, highly specific leaves. In larger trees, this constraint would improve generalisation. 
The unrestricted Scikit learn tree achieved training accuracy because it continued to split until leaves were pure. This behaviour reflects the low bias nature of the decision trees when given enough depth, they can perfectly fit training data. However, behaviour like that risks overlifting, as the model may capture noise instead of general patterns. In this dataset, overfitting was limited due to strong call separability, but the slight drop from 1.0 to 0.9855 on the test set confirms that some over specialisation occurred. 
Comparing the splits between the scratch implementation and Scikit lean reveals differences in optimisation. Scikit lean internally checks and evaluated the splits more efficiently and handles categorical encodings effectively. The scratch implementation, while correct, it lacks advanced optimizations and therefore selected splits that did not maximise class separation as best as it could.
Building the tree from scratch provided good insight, it required explicit computation of impurity, manual split evaluation, and recursive structure design. This deepened understanding of how decision trees behave and why they make it specific decisions. However, building from scratch sacrifices computational efficiency, robustness and the optimisation found in mature libraries .
In health related applications the shallow tress are often preferred because interpretability and reliability are key. A depth 2 or even depth 3 can be easily visualised and audited by clinicians. Deep trees could provide slightly higher accuracy but at the cost of complexity and reduced transparency. In sensitive domains, preventing overfitting and ensuring explainability are sometimes more important than marginal accuracy improvements.
Overall this project shoed a strong understanding of decision tree mechanics, including impurity measurement, greedy splitting behaviour, overfitting dynamics and pruning strategies. The comparison between library based and manual implementations gave insight into algorithmic design and performance trade offs as well. The experiments clearly showed how tree depth influences bias and variance, and how implementation details affect classification outcomes.
